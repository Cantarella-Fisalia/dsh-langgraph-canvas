## 2. 可复跑的主功能预检

```powershell
cd E:\Heng\vis4agent
npm.cmd test
npm.cmd run build
npm.cmd run acceptance:preflight
```

可指定报告位置，例如 `npm.cmd run acceptance:preflight -- --report .tmp/acceptance/recheck.json`；Node 24+、Python 3.11+，解释器选择与插件相同（LANGCONTOUR_PYTHON / 本机 D:/Anaconda/python.exe / python）。

预检启动自己的随机端口 HTTP 服务，加载实际插件模块并提供最小 webServer/effect 测试上下文，路由到真实后端与 Python worker；检查生产 HTML/JS/CSS 摘要、来源、API 前缀、循环／汇合／路由示例、State、SSE、布局、确认生成、审阅摘要、应用、外部冲突、逐字节撤销、持久记录以及卸载。只修改三个示例的自有临时副本，结束后清理。

它不加载真实 Harness 服务，不启动桌面或读写任何 profile，不注入合成行为 adapter，不提交模型任务。报告包含代码及构建摘要、各项结果和证据边界；`realHarnessConnected:false`、`desktopAcceptance:not_performed` 和 `acceptance:not_accepted` 不得改写成通过。若后续接入了 adapter，预检仍只查询其能力，不自动发起真实模型任务。

| 退出码 | 含义 | 后续动作 |
|---|---|---|
| 0 | 主功能预检通过；可选的真实宿主查询也已就绪（若指定） | 继续真实桌面清单，仍不代表整体完成 |
| 1 | 检查或清理失败 | 根据报告的失败项定位并修复 |
| 2 | 检查通过，但指定的真实宿主能力未就绪 | 检查宿主服务与默认模型后复跑 |

默认预检使用无模型服务的最小上下文，能力不可用提示是预期结果，不表示 adapter 缺失。可追加 `-- --harness-url http://127.0.0.1:端口` 只查询实际宿主能力；不自动执行模型任务。

原始报告默认 `.tmp/acceptance/latest.json`；2026-10-24 甲方实测副本见 [预检 JSON](../handoffs/main/FINAL-ACCEPTANCE-001.preflight.json)。该报告未独立观察 OS 中 worker PID 的退出；须由 D12 验证，不把 SSE 关闭等同于进程已退出。
