## 3. 代码走查要点

`analysis-evidence.js` 的职责边界清楚，符合"adapter 只规划、worker 才是最终裁判"：

1. 用**本次任务**实际提供的读段建立覆盖表（`supplied` + 文件哈希），旧任务历史天然不进入覆盖；
2. 对每条引用按 `line..endLine` 求缺口，同文件相邻/重叠读段合并后可共同覆盖（对应"跨相邻已读段的合法引用不再被误拒"）；
3. 缺口按文件聚合、就近打包成 ≤300 行请求，避免零散小引用耗尽轮次；
4. 未知文件、越界行号、参考目录（docs/examples/tests/…）直接抛错，不进入读取；
5. 不解析、不猜补、不执行文本——只产出读取计划。

与甲方描述的"补读前回复不直接采用""共用六轮/五分钟预算"一致；这部分由 adapter 测试覆盖，我复跑通过。
