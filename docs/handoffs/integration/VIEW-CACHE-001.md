## 3. 未独立复现的部分（说明原因）

第 9 项的**快照路径本身**没有被我证实：我用的导航方式（点侧边栏「插件」再点回会话）很可能只是隐藏而非卸载主区域，iframe 一直存活，所以看不到"缓存视图"状态——也就无法区分"快照秒开"和"视图根本没被销毁"。要真正复现，需要能强制卸载前端状态的操作（甲方用的是切到"轨迹"再返回）。这一条只作为"返回时没有读取等待"的观察，不作为快照机制通过的证据。

同理未验证：3 个工作区 / 150 万 code units 上限、超过一天停用、存储被拒时的内存回退。

## 4. 结论

缓存策略层面与交付说明一致：`preferCached` 的短路面可用且返回 `reused:true`，静态资源与入口 HTML 的缓存头区分正确（哈希资源 immutable、入口 no-cache、API no-store），回归检查全过。

用户侧：桌面仍 0.6.0，**完全退出重开**才是 0.6.2；实际"来回切换是否顺畅"以你的主观体验为准——如果仍觉得慢，告诉我你切的是哪个入口（侧边栏会话 / 轨迹页签 / 关闭再开），我按那个路径去复现。
