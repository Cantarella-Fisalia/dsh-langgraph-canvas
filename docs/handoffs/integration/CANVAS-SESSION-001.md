## 3. 关键观察

1. **不再偷偷回落到默认模型**：没有活动会话时 `/analysis-support` 与宿主 `behavior.available` 都返回 false 并给出明确原因。这正是本批"AI 必须走当前会话"的要求，也避免了我上次担心的"无会话也发起独立模型请求"。
2. **画布空间明显变大**：State、诊断、来源都改成按需展开，主视图只剩图本身，符合"画布优先"。
3. 会话绑定使 AI 按钮的可用性依赖当前会话状态；在未选会话或会话忙碌时按钮应不可提交（甲方有"会话忙碌不新提交"的说明，我未在真实忙碌状态下复测）。

## 4. 未验证（如实记录）

1. **会话内 AI 真实调用**：点击 `✦ AI` 会把任务写入当前会话并调用该会话模型（真实计费、进入对话历史）。我没有触发。因此以下未由我独立确认：回复进入原对话、插件回合工具被隐去（`tools.guard`）、普通下一轮恢复工具、steer 消息延后。
2. **桌面验收**：桌面仍是 0.3.0，需完全退出重开；旧宿主下 `✦ AI` 不会工作。
3. 会话切换（同工作区不同会话）时桥接更新、忙碌态按钮禁用，未逐项点击。

接入层无阻塞：v0.6.0 在真实 Harness 实例加载正常，会话绑定生效且失败时给出可读原因，画布优先布局与 State 浮动控件渲染符合交付说明，回归检查（行为、分析、会话通道、预检）全部通过。
