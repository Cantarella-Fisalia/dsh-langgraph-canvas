# AI-RESTORE-001：切换视图后恢复 AI 任务

2026-10-26，甲方交付 v0.6.1，主计划 v0.21。

用户反馈：架构页解读仍在后台执行，切换轨迹后再回来，前端进度消失，又能点击新提交。原因是 ConversationAI 的本地 React 状态随 iframe／视图卸载丢失，后端只有按任务 ID 查询，页面重建无法发现原任务。

## 修复

- 后端增加按项目／会话查询任务快照：优先本会话活动任务，再定位指定请求编号，最后恢复最新终态。另一会话占用只返回阻塞标记，不返回它的任务，不误取消。
- 页面挂载先同步后台，完成同步前不能新建请求。恢复原任务编号、已读文件数、进度和取消入口；离开期间已完成、失败或取消，也能恢复终态。每 1.6 秒更新，离开只停止观察，不停止任务或启动模型。
- 提交前保存标签页内原请求号、原源码版本与后端 runtimeId。回执不确定时，明确再点击复用原编号，不创建新的排队请求。迟到查询与旧组件的响应不能覆盖新状态；在支持检查期间离开不会迟到提交。
- 查询失败时按钮只重查 GET，不把状态未知当作任务已空闲；存储不可用仍能从后台发现已登记任务。后端重启会使 runtimeId 改变，本地旧票据清除并提示核对，禁止自动重发模型请求。

范围：前端任务观察、后端快照 API、协议与客户端、版本和对应文档／测试。没有修改会话模型选择、源码解析／写回权限、生产 profile 或乙方交付记录。

## 验证

107 项自动检查（56 Node＋51 Python）、类型检查、构建、11 项插件预检通过。新增测试覆盖视图重建、离开期间完成、恢复后取消、其他会话／项目隔离、首次同步门禁、迟到查询、回执尚未返回、回执丢失复用编号、查询离线、后端重启、存储拒绝，以及支持检查期间离开。

实际安装的 Harness，在自有隔离 DSH_HOME/profile 中使用可暂停的确定性提供方，验证“架构 → 启动一次 AI → 轨迹 → 架构”：任务编号始终为 fb086c6c-5eaf-4bcd-b214-f2bdc9be3e9e，恢复后显示进行中、已读 3 文件和取消按钮。再次离开，在轨迹期间放行该任务完成，再回来显示同编号完成状态。提供方记录只有 1 次解读调用，工具数 0，没有额外排队请求。未用用户账号模型，未重启生产桌面。

证据：[结构化记录](AI-RESTORE-001-evidence.json)、[运行中恢复 DOM](AI-RESTORE-001-running-dom.md)、[完成后恢复 DOM](AI-RESTORE-001-done-dom.md)。截图接口仍返回 Unable to capture screenshot，因此本次保存真实 DOM 和模型计数，不宣称完成像素验收。

## 加载与边界

若当前旧版任务仍在执行，先在轨迹等待完成，再完全退出并重开 Harness 加载 v0.6.1。旧版已经丢失的页面提示不能通过磁盘更新直接补到旧内存实例；本补丁在新版后端加载后生效。

后台任务仍保存在本次宿主实例的内存里（上限 100，终态可淘汰）。支持页面／iframe 重建与同一后端内的刷新，不跨宿主重启自动续跑；已生成结果仍按源码版本缓存。恢复页面只查询，只有用户明确点击才可能开始或取消任务。
