## 范围与设计

用户要求条件流转加入菱形，调用其他图使用特殊形状。采用展示层流程图：START/END 终止符、矩形执行步骤、独立菱形路由、双竖线框图调用步骤。自动排布改为从上到下的分支层次，保留用户已保存的位置。

菱形由已有 conditional 边按来源、路由与注册位置分组，保留原始分支边 ID、路由源码与编辑入口；不是新业务节点，不进入源码、草稿或布局协议。普通并行出边、等待汇合不转换成判断。调用标记仅使用同版本已核对的图关系，区分直接注册子图与函数内部调用，不依据文件名或 IntentNavi 专用规则猜测；关系缺失时保持未知。

涉及：apps/frontend/src/App.tsx、styles.css、新 flowchart.ts 与测试、scripts/dev/test.mjs、主计划、README、USER_GUIDE、开发交接和本交付记录。不修改 Harness 适配代码、插件清单、profile、用户业务源码；不新增依赖或模型请求。

## 实现与基本验证

- 新 flowchart.ts 仅投影已有图：菱形按同一来源／路由／注册区间分组，原始条件边对象与 ID 保留，普通并行／等待汇合不变。自动排布按最长前向路径让汇合排在所有前置节点之后，保留回环与孤立节点。
- 新 flow-canvas.tsx 提供流程图形状，调用框内目标可切图；节点详情列出关系解释与调用链证据。条件详情列出该菱形的全部分支，选择后仍编辑原边。未保存布局切图仍走既有确认。
- 调用标记只用同源码版本的关系且排除未应用节点草稿、隐藏目标、共用 State 和待确认关联；函数内部调用保持函数身份。条件草稿不套用旧 AI 判断说明。
- 虚拟菱形不可拖动、不可建立源码连线、不写入布局；位置随真实来源步骤计算。保留旧位置，用户点击自动排布后才选择保存。源码写回确认链保持。
- 修复 React Flow 数据更新时丢失 measured 尺寸，点击节点、分支和模式切换后真实节点继续显示。
