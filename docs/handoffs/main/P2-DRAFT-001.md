# P2-DRAFT-001：画布结构草稿与确认入口

日期：2026-10-23。负责人：甲方。状态：主功能完成，待接入。依据：用户要求将剩余五步纳入计划，并先做第一步；只有点击确认才向 Harness 提交修改命令。

本批登记写入范围：apps/frontend/src/App.tsx、styles.css、新增 editor.tsx；packages/contracts/src/editing.ts 及测试；packages/api-client/src/index.ts；apps/backend/src/application.ts、新增 edit-requests.ts 及测试；根 package.json 的检查命令；PROJECT_PLAN.md、README.md、DEVELOPMENT_HANDOFF.md 与本批 API／交付文档。不修改 plugins/harness、桌面 profile 或乙方验收文件。

目标：编辑节点、普通／条件／汇合连线和 State 字段，记录本地结构草稿，展示修改清单，并以单独的确认按钮控制提交。后端提供可注入的请求接收接口，校验确认标志、源码版本及幂等请求；默认接入通道未配置，界面明确提示待接入。

本批不实现源码写回、代码差异、修改事务或真实 Harness 编码执行。接入接口只接收已确认的结构意图；不得绕过后续步骤直接修改原项目。未经点击确认，编辑、拖动、保存布局、切换面板及读取通道状态均不得提交任务。

## 已实现

- “编辑结构”模式，节点新增／修改／改名／删除；改名同步连线端点，删除节点清理关联边及相关汇合组，保留业务函数的删除策略。
- 普通／条件／整组汇合连线的增改删；拖拽端口打开已填好起止节点的表单，取消不会产生修改。START/END 固定，非法端点与重复分支在本地／后端均校验。
- 共享 State 字段增改删与原始类型注解；State 继续置顶，不更换原图 State 引用，不执行注解文本。
- 草稿按项目和图保存在浏览器本地，刷新后恢复；源代码版本变化时保留草稿、阻止提交。编辑、查看清单和恢复均无自动任务提交。
- 修改清单预览与独立“确认并交给 Harness”按钮。未接收通道时最终按钮禁用并明确提示；接收成功保存回执并阻止重复提交。
- 真实 HTTP API 校验确认标志、当前源码版本、草稿结构与请求编号；同进程去重并发请求，失败保留可重试的请求编号。

字段语义、动态构图和完整 Python 语法检查仍属于后续源码阶段；本阶段仅有静态结构检查与意图记录。类型注解未被求值；条件分支当前按文本记录，具体 Python 字面量类型待源码阶段核对。草稿位置仅预览，尚不随结构草稿持久化；清除本地回执不取消已接收请求。跨窗口草稿合并和持久任务状态在后续阶段处理。

## 验证结果

环境：开发 Node 24.13.0、Python 3.12.3。22 项自动检查（13 Node + 9 Python）、TypeScript 检查与 Vite 生产构建通过。React Flow use client 打包提示仍不阻断产物。

真实浏览器操作：在隔离的 research-team 源码副本上新增 audit 节点、修改名称为 audit_checked、添加 audit_ok:bool、普通边、两条汇合组边、修改条件分支；恢复六项草稿、实际拖拽端口打开连线表单并取消、移除整组汇合、移除节点及相关边、放弃草稿恢复原图。浏览器控制台未见错误。

确认提交使用单独的模拟接收器（仅记录请求，不修改文件）和生产构建：

| 操作 | 接收次数 |
|---|---|
| 编辑并保存本地草稿 | 0 |
| 打开修改清单 | 0 |
| 点击最终“确认并交给 Harness” | 1 |
| 刷新并重新打开项目 | 1，已接收草稿保持锁定 |

测试副本中的三个 Python 文件 SHA256 前后一致。记录见 [confirm-test.json](P2-DRAFT-001-confirm-test.json)。API 检查同时覆盖未确认拒绝、通道未接入、非法结构、过期源码、同请求号并发去重、请求号复用及适配器失败重试。
