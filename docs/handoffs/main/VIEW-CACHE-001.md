# VIEW-CACHE-001：架构页临时快照与快速重开

2026-10-26，甲方交付 v0.6.2，主计划 v0.22。

用户反馈每次点击架构都显示读取中，要求顺畅切换。原有 .vislang/analysis-cache/latest.json 只缓存 AI 派生结果，layout.json 保存布局；视图卸载后 App 会清空本地项目／图／布局，并重新 POST 打开项目与读取布局。后端虽有内存 analysis，原打开流程也每次全量扫描。已有两种文件缓存没有消除这一串行等待。

## 变化

- 工作区页面快照保存在标签页 sessionStorage，按 API 基址与工作区隔离，包含项目、结构与解读、所选图、参考图选项、已保存布局及对应源码版本。返回先显示快照，后台再打开／校验真实项目；同版本核对不再把布局清空。布局保存成功也更新快照。
- 后台核对前仅允许查看和恢复原任务观察，禁用新 AI、结构修改、布局保存和源码提交；已有真实任务仍可取消。失败时保留快照、提示错误，刷新按钮重试打开项目。缓存不是编辑或写回的事实来源，所有源码事务依旧真实验证。
- 快照最多三个工作区、每条 150 万 UTF-16 code units、总预算 200 万 code units，超过一天停用。损坏／超限回退正常读取，存储拒绝时当前页面可用内存回退，不阻止项目读取。缓存位于浏览器会话，不给用户源码目录再加临时文件。
- 后端 POST /projects 可选 preferCached:true；仅在文件 watcher 可用、未报告变化、无正在进行的扫描且验证结果在三秒内时复用，返回 reused:true。文件事件立即失效；扫描期间发生变化不会把结果误标为干净。AI 缓存更新也失效。普通打开、手动刷新和所有写入路径不使用这个短路。
- Vite 内容哈希 JS/CSS 可 immutable 缓存；入口 HTML 继续 no-cache，API no-store。重建 iframe 可复用同版本大资源，升级后新哈希引用新资源。旧完成任务已随项目缓存读取时，不再仅因重建 AI 按钮额外触发全量图刷新；新完成任务仍更新结果。

## 验证

110 项自动检查（59 Node＋51 Python）、类型检查、构建、11 项插件预检通过。新增快照重建、图／布局保留、API／工作区隔离、过期／损坏／超限／存储拒绝回退测试；后端检查快速重开确实复用，Python 文件修改后立即重开会看到新版本，旧源码写回仍冲突。静态预检核对哈希资源 immutable、HTML no-cache 与产物摘要。

## 限制与加载

首次打开新项目、缓存过期／超限／存储不可用，仍需要读取。iframe 与 React Flow 自身初始化仍会耗时，不承诺所有设备零延迟。只恢复所选图及已保存布局；未保存拖动、缩放、State 展开状态不在本批范围。会话关闭后快照可丢弃；AI 文件缓存和已保存布局不受影响。不能用快照跨宿主重启自动续跑任务。

等待当前旧任务完成后，完全退出重开 Harness 加载新版；无需重装链接插件或上传 GitHub。
