# AI-JSON-001：原会话中的 JSON 格式纠正

2026-10-26，甲方交付插件 v0.6.3，主计划 v0.23。状态：主功能修复与隔离原生验证完成，交用户桌面试用；不代替乙方和用户账号的最终验收。

## 原因与范围

用户报告任务读取 7 个文件后提示“当前会话没有返回有效解析 JSON”。只读检查与该报错相关的会话：对应回合以 completed 正常结束，回复约 4.3 万字符，JSON 字符串与内部数组／对象已闭合，但最外层对象缺一个闭合括号，JSON.parse 在结尾拒绝。不是读取项目失败、工具未接通或模型请求未发出。不得把“已读取文件数”当作结果通过校验。

不把用户实际回复、项目源码或完整对话放进交付记录／测试；回归使用独立合成数据。诊断没有调用用户模型，也没有修改其项目和生产 profile。

涉及 plugins/harness/lib/analysis-adapter.js、对应适配器测试、apps/backend/src/deep-analysis.test.ts；同步插件版本、使用指南、深度解析 API、主计划及交接汇总。宿主适配文件按用户此前要求补全真实会话通道的范围临时代修，原维护责任仍属乙方；不修改安装、鉴权、生产配置或乙方验收记录。同步前以文件摘要检查并发变动。

## 行为

- 提示模型返回完整且紧凑的 JSON，明确 architecture 与顶层 message／unresolved 的边界。
- 完整 JSON 或完整 JSON 围栏使用严格 JSON.parse。格式失败时在原会话至多一次纠正；原生历史已含错误回复，不重新复制大段内容。纠正计入六轮与五分钟上限，任务状态显示纠正进度，继续沿用当前会话模型及无工具边界。
- 不猜补括号、不截取片段、不执行文本、不提前采用无效 JSON 中的读取请求。纠正后返回读取请求按原预算处理，最终对象按原结构、证据与源码版本校验；未读证据仍失败。
- 取消、输出超限、工具调用与异常结束不触发格式纠正。再次格式错误／轮数已用尽明确停止。原静态图和已保存解读缓存保留，不修改源码，不自动再排一个任务。

## 验证

类型检查与 119 项自动检查（68 Node＋51 Python）通过。新增 7 个适配器回归和 2 个后端／真实 Python 校验路径回归：合成约 4.4 万字符的缺括号 JSON、完整围栏、再次失败与正文隐藏、六轮上限、纠正后继续代读、纠正中取消、异常结束不重试；纠正后缓存成功、随后失败保留旧缓存、未读证据仍被拒绝。其余任务恢复、视图缓存和源码审阅／应用检查继续通过。

真实隔离 Harness 使用独立两行 Python 文件与确定性测试提供方，调用实际 Agent 和分析适配器：第一轮故意返回缺外层括号 JSON，第二轮同会话修正；两轮均 conversation-only 模型、tools=[]，第二轮历史含第一轮原始回复，仅代读一次。普通第三轮工具恢复，源码字节不变，用户账号模型调用为 0。脱敏结果见 [AI-JSON-001-evidence.json](AI-JSON-001-evidence.json)。该验证证明宿主调用与恢复流程，不评价真实模型生成业务解释的质量。

## 使用与限制

等待旧任务结束后完全退出重开 Harness，点击架构页小“✦ AI”按钮。格式错误会出现“正在当前会话自动纠正”，无需立刻手动再点；二次纠正可能消耗额外模型用量，仍在六轮内。若已经没有剩余轮次或仍失败，保留原图并提示原因，用户可以明确再试。
