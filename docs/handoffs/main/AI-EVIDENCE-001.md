# AI-EVIDENCE-001：补读当前任务缺失的源码证据

2026-10-26，插件 v0.6.4，主计划 v0.24。甲方主功能修复及原生隔离验证完成，交用户桌面试用；不代替乙方的最终验收。

## 原因

用户任务读取三文件后提示“AI 必须先读取并引用确切的源码区间，不能编造文件或行号”。针对性只读核对原会话发现，模型生成了合法 JSON，但沿用同会话历史任务的源码；当前任务实际证据只包含初始三段，另有 145 处引用未被当前段覆盖。175 个不重复引用涉及七个实际业务文件，文件与行号均存在，不能一概断言为编造。静态图位置与对话记忆不能替代当前任务的源码版本证据。

旧 adapter 接到最终 graphs 就结束，缺少补读并重新核对的恢复流程；worker 还要求一条引用必须包含在单个读取段，错误拒绝跨相邻已读段的合法引用。

诊断仅输出引用数量／读取规划等摘要，没有将用户源码、实际回复或完整会话复制进交付／测试，也未执行或修改业务项目。离线校验只用于定位，不保存缓存或直接采用旧回复。

## 修改

- 每次分析新建 analysisId；每轮携带 revision 和本次 suppliedRanges，明确旧任务与索引元数据不算本次证据。前端 task.id／requestId 及恢复协议保持原样。
- 对已知图／解读协议中的引用预检。有效但未读的区间先减去当前覆盖，按文件聚合附近缺口及其间上下文，每段最多 300 行，每批六段；再要求同会话模型依据新源码重新核对，返回完整 JSON。补读前的回复不直接采用。忽略任意附加键中的伪位置，不借其触发读取。
- 模型最终返回仍经 Python 完整校验。当前版本同文件相邻或重叠的区间可以共同覆盖引用；缺一行、跨文件或旧版本仍失败。错误指出实际文件、行号和当前已读范围。
- 补读、格式纠正和显式 readFiles 共用六轮／五分钟／40 段／768 KiB，未扩大预算。未知／参考路径、无效或越文件行号立即拒绝；最后一轮仍缺证据时不再补读。取消或源码变化停止后续读取、模型调用及缓存。原图和既有解读保留。

涉及 plugins/harness/lib/analysis-adapter.js、新增 analysis-evidence.js、对应 adapter 测试、后端深度解析测试、Python deep_analysis 及其测试；更新版本和主计划、API、使用指南、交接汇总。本轮按用户此前补全当前会话 AI 通道的授权临时代修宿主 adapter，原维护责任仍属乙方；未更改生产 profile、鉴权、安装或乙方记录。同步前逐文件核对摘要，不覆盖并发修改。

## 验证

130 项自动检查（77 Node＋53 Python）及类型检查：新增历史任务重新读取、每轮任务编号与证据清单、最多六段与 300 行拆分、附近碎片聚合、未知路径／越界拒绝、末轮不追认、补读中取消、仅采用重新核对后的回复、核对中源码变化、同版本连续覆盖／缺口／旧版本等回归。上版格式纠正可与补读串行使用，仍共用预算。

真实隔离 Harness 确定性提供方：同一原生会话连续两次解析；第二次第一轮故意引用旧任务读过的文件，adapter 重新读取该文件并发起第二轮核对，只采用 RECHECKED 回复。四轮解析均沿用 conversation-only 模型、tools=[]；两任务编号不同，各自后续轮一致。普通下一轮恢复工具，源文件字节不变，用户账号模型调用 0。详见 [脱敏证据](AI-EVIDENCE-001-evidence.json)。验证证明恢复路径，不证明真实模型的业务解释质量。

对用户实际失败回复进行只读离线规划：不调用模型、不写缓存，新版在一批六段补读后没有剩余缺口，总计九段、66,161 字节，完整 worker 校验通过三张图的解读；详见证据中的 offlineDiagnostic。该结果未作为正式任务结果采纳。

同步至实际 E:/Heng/vis4agent 后，类型检查、130 项测试、生产构建和 11 项插件预检全部通过；预检加载 v0.6.4。实际预检报告 .tmp/acceptance/AI-EVIDENCE-001.json 的摘要及修复源码摘要纳入证据。报告明确 desktopAcceptance=not_performed，完整 Electron 桌面及用户模型质量验收仍需试用。隔离实例已停止，4336 端口释放。

## 加载与限制

等旧任务结束，完全退出重开 Harness，架构页点击小“✦ AI”。发现缺口时会显示补读、重新核对解读，不必立即重试；所选模型的额外核对用量仍由原会话承担。任意模型不保证每次都完成，超预算或证据不成立会保留原图并明确失败。读过正确位置也不证明解释语义一定正确；修改源码仍单独审阅确认。
